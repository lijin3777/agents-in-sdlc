GitHub Copilot を agent mode で使うと、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。作業は自分のマシンでリアルタイムに行われるため、VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集を実行中に確認できます。差分をインラインでレビューし、変更ごとに適用または却下できます。また、エディターを離れずに追加のプロンプトを送って会話を誘導し、作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイルの編集をレビューして適用する。
- セッションの途中でエージェントを誘導し、ハイコントラストモードに加えてライトモードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用のカスタムエージェントが、ハイコントラストモードを実装しています。作業の途中でデザインチームから追加の依頼があり、既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替えも追加したいとのことです。最初から新しい会話を始めるのではなく、既存のセッションを誘導して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集などを確認できます。ファイルの編集はそれぞれ差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択して変更を適用します。
    - **Undo** を選択して変更を元に戻し、別の方法で作業するようエージェントに依頼します。
4. チャットの上部にある **Files changed** インジケーターを開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの使用許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードを実装するまで待ちます。最後に、実施した変更をまとめたメッセージが表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは前の作業からコンテキストを引き継ぎます。変更したコンポーネント、使ったスタイルの方法、設定したローカルストレージのパターンなどが含まれます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業を引き継いで変更を調査し、ライトモードの追加を提案します。
3. ハイコントラストモードの場合と同様に、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが希望しない方向に進んだ場合 (たとえば、切り替え UI を意図しない形でリファクタリングしようとした場合) は、チャット入力欄の隣にある **Stop** ボタンで作業を停止してから、追加の説明を送信できます。

> [!TIP]
> 進行中のセッションを誘導する方が、最初からやり直すより短時間で済みます。追加のプロンプトで調整を依頼できます (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」など)。方向を修正できます (「3 つ目の切り替えを追加せず、ライトモードを既存の設定パネルに追加する」など)。範囲を広げることもできます (「両方の切り替えにキーボードショートカットも追加する」など)。

## 変更されたファイルをレビューする

変更をコミットする前に、エージェントが編集した内容をすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の維持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで変更を公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して誘導しました。ファイルの編集を適用するたびにレビューし、個々の変更を採用または却下し、コンテキストを失わずに作業を広げる追加プロンプトを送信しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- ファイルごとの編集を適用または却下しました。
- セッションの途中で追加プロンプトを送り、エージェントを誘導しました。
