フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、すべて 1 つのブランチに保存されています。まとめてレビューし、プルリクエストを開きましょう。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスを任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントをいくつかの PR に分けます。ワークショップを簡略化するため、フィルター機能と品質ワークフロー全体を 1 つのセッションとブランチにまとめ、1 つの PR に含めました。

このレッスンでは、次のことを行います。

- Agent Merge とは何か、マージまでのライフサイクルを自動化する方法を学びます。
- 機能の PR 全体と検証の根拠を確認します。
- レビュー後に限って Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフローでは、Copilot を使って機能を計画、実装、検証してきました。Tailspin Toys では、マージの許可を開発者の判断に委ねたまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み込み、CI チェックの失敗、レビューコメント、必要に応じたリベースなど、マージを妨げる問題に対処します。GitHub が許可すると、PR をマージします。バックグラウンドで動作し、アプリを再起動しても継続し、プルリクエストがマージされると自動的に停止します。

これまでは自分で **Merge pull request** を選択していました。Agent Merge にその役割を任せることもできますが、コードの編集やマージには引き続き明示的な許可が必要です。マージを許可する前に、許可する操作と作業内容をレビューしてください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したので、Agent Merge に PR プロセスを管理させましょう。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンのオプションを選ぶだけでは開始されません。

Agent Merge のプロセスが始まります。次の作業を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- issue からセッションを開始した場合は、説明の本文で関連する issue を参照します。
- ターゲットブランチに対してリベースするか、マージ競合に対処します。
- CI プロセスを監視し、すべてのチェックが成功することを確認します。
- 他の開発者または Copilot code review からのフィードバックがないか PR を監視し、コメントを解決するために変更を行います。
- 任意で、すべてのチェックが成功したら PR を自動的にマージします。

すべてのチェックに成功した後、Agent Merge が PR もマージするようにします。

5. マージを許可する前に、PR の差分と検証の根拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. 次のように明示して、エージェントにマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進行状況を確認し、報告されたブロッカーに対処します。続行する前に、PR の状態が **Merged** になっていることを確認してください。マージの許可を有効にしたことや、エージェントが動作中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限の不足を回避しません。続行する前に、これらのブロッカーを解決してください。
