最初は小さな機能をプロジェクトに追加しましたが、大きな変更には、より確実なプロセスが必要です。GitHub Copilot は組織の既存のワークフローに沿って動作するため、適切な方法で必要な機能を構築できます。このレッスンから数回にわたり、一般的なエージェント駆動型の開発プロセスに沿って進めます。まず issue を使って新機能を作り、コードの妥当性と機能の動作を確かめたうえで、プロジェクトにマージします。

> [!NOTE]
> 機能開発を続ける間、同じ会話とブランチを使います。通常は、作業するファイルの種類ごとに異なるブランチや PR を使いますが、ここでは主要な概念に集中するために手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub issue から新しい Copilot の会話を始めます。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動検証します。

この機能開発を続けるなかで、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加し、QA エージェントを作成して、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がゲームをカテゴリーや発行元で絞り込める必要があります。バックログの issue には機能が説明されていますが、カテゴリーの組み合わせ方など、コーディング前に合意が必要な詳細もあります。Plan モードでそうした判断を整理し、範囲を限定した実装を Autopilot に許可します。

## 背景

AI コーディングエージェントを開発ワークフローに取り入れても、基本は変わりません。むしろ、基本がこれまで以上に重要になります。多くの開発者は、次のような流れで作業します。

1. 実装する内容を説明した issue から始めます。
2. 構築する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行して検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> チームや組織によって詳細は異なりますが、多くの場合は上記の流れに近い形になります。

この標準的な手順に沿うことで、AI が生成したコードが要件を満たし、手書きのコードと同じ審査を受けるようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更案を提示し、次の操作に進む前に入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。計画中はプロジェクトファイルを編集できません。
- **Autopilot**: エージェントが自律的に作業し、タスクが完了するまでコードを書き、テストを実行して、改善を繰り返します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue から始める

フィルター機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルを準備します。

1. Codespace に戻ります。停止している場合は、再起動してから続けます。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター機能用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 矢印キーを使って、**Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) で始まることを確認してください。`#` を使うと、GitHub 上の issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てると、機能の実装やタスクの実行を Copilot に任せる前に、進め方を決められます。複雑な作業では、計画に時間をかけることをお勧めします。Plan モードに切り替えて、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した issue の参照に続けて、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調査し、最適な方法を判断して、計画の作成に取りかかります。

3. フィルター機能の動作について質問された場合は、希望に合わせて回答します。どの回答が正しいということはありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 上下にスクロールして計画を確認します。
6. 自分の判断と異なる箇所があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を書いてレビューできたら、Copilot に作業を任せて実装します。Autopilot では、Copilot が完了したと判断するまで、問題への対応を繰り返します。

1. **Accept plan and build on autopilot (recommended)** またはインストール済みのバージョンで同様の名前が付いたオプションを選択します。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、すぐに実装が始まることがあります。先に計画を確認してください。Copilot が依存関係の不足やポートの競合を報告した場合は、チェック完了と判断する前にセットアップの問題を解決します。

## 実装をレビューして検証する

コードを生成したら、ほかのコードと同じように、マージする前にレビューする必要があります。コードをレビューし、サイトを実行して問題がないか確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルター機能の実装とテストを確認します。
3. 結果を issue と計画で決めた内容に照らし合わせます。
4. コードのレビューが終わったら、<kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に解決を依頼します。

## 新機能を試す

コードに問題がないことを確認したら、アプリが動作するか試しましょう。前回と同じようにアプリを起動し、Codespaces で転送されたポートからサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. カテゴリーによる絞り込み、発行元による絞り込み、計画で合意した組み合わせを試します。
4. リセット時と結果がない場合の動作が、issue と合意内容に一致することを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーの停止を依頼します。

## まとめと次のステップ

異なる会話モードを使って機能を作成し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub issue から新しい Copilot の会話を始めました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動検証しました。
