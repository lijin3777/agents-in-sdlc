フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、すべて 1 つのブランチに保存されています。まとめてレビューし、プルリクエストを開きましょう。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にプロセスを任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントをいくつかの PR に分けます。このワークショップでは手順を簡略化するため、フィルター機能と品質ワークフローの作業全体を 1 つの会話とブランチにまとめ、1 つの PR に含めました。

このレッスンでは、次のことを行います。

- Agent Merge とは何か、マージまでのライフサイクルを自動化する方法を学びます。
- 機能の変更全体と検証の根拠を確認します。
- フィルター機能の PR を作成します。
- レビュー後に限って Agent Merge を有効にし、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフローでは、Copilot を使って機能を計画、実装、検証してきました。Tailspin Toys では、マージの許可を開発者の判断に委ねたまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、プルリクエストをマージ可能にするために必要な残りの作業を自動化します。有効にすると、Copilot は PR をブロックしている問題 (失敗した継続的インテグレーション (CI) チェックの修正、レビューコメントへの対応、必要に応じたリベースなど) に対処し、リポジトリで許可されている場合は GitHub の自動マージを有効にします。

これまでは自分で **Merge pull request** を選択していました。Agent Merge にその役割を任せることもできます。Agent Merge を有効にする前に、作業をレビューして準備ができていることを判断してください。

## Agent Merge で PR を管理する

コードの作成が完了したので、全体をレビューし、PR を作成して、残りのプロセスを Agent Merge に任せましょう。

1. Codespace に戻ります。
2. `/agent` を入力してエージェントのダイアログを開きます。
3. オプションの一覧から **Default** を選択し、<kbd>Enter</kbd> を押します。
4. `/pr create` コマンドで新しい PR を作成します。
5. `/pr agentmerge` を実行して Agent Merge を有効にします。
6. Copilot が PR の継続的インテグレーションの状況を監視します。すべてのチェックが成功すると、マージを実行します。
7. Copilot から「PR #14 was squash-merged successfully.」のようなメッセージが表示されたことを確認します。

> [!IMPORTANT]
> Agent Merge は、必須の承認、ブランチ保護、マージキュー、リポジトリの設定、権限の不足を回避しません。処理がブロックされた場合は報告された理由を確認し、リポジトリで許可されている場合は、レビュー済みの変更を手動でマージしてください。
